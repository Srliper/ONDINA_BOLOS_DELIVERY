# Ondina Bolos — notas para quem mexer no código

- O cardápio fica na rota inicial (`src/routes/index.tsx`). O pedido é montado no carrinho, passa pelo checkout (endereço, forma de pagamento, resumo) e é finalizado numa conversa de WhatsApp; não há cobrança no site (o QR Code do Pix é só ilustrativo).
- Produtos com foto: `src/data/products.ts`. Sabores completos do cardápio: `src/lib/bakery-menu.ts`. Preços sempre como número, formatados com `formatBRL` (`src/lib/format.ts`).
- Formato da mensagem do pedido: `src/lib/whatsapp.ts` (coberto por `src/test/whatsapp.test.ts`). `processOrderAndSend` registra o pedido no webhook do n8n (`VITE_N8N_WEBHOOK_URL`, com tempo limite e erro silencioso) e sempre abre o WhatsApp depois — o n8n nunca pode impedir o pedido.
- Checkout em etapas: `src/components/CheckoutStepper.tsx`; regras e validação (Zod) em `src/lib/checkout.ts`.
- Visual centralizado em `src/styles.css`; variantes de botão em `src/components/ui/button.tsx`.
- Movimento: CSS + `src/components/MotionRoot.tsx` + `src/lib/fly-to-cart.ts` no site; Framer Motion só nas telas imersivas (Monte seu Bolo em camadas em `src/components/BoloBuilder.tsx`, sempre dentro de `<MotionConfig reducedMotion="user">`). Confete só via `celebrate()` em `src/lib/confetti.ts`. Toda animação precisa respeitar `prefers-reduced-motion`.
- Intro do topo: `src/components/ScrollIntro.tsx` (contas em `src/lib/frame-sequence.ts`) desenha em canvas os frames de `public/intro/frames/frame-0001.jpg` … `frame-0240.jpg` conforme a rolagem; com movimento reduzido mostra só o frame 96. Ela vem antes do `<Header />` em `src/routes/index.tsx` (tela cheia, o menu só aparece depois) e marca `data-intro` no `<html>` para esconder o WhatsApp flutuante enquanto cobre a tela. Os frames são ilustração gerada (por isso o aviso "Imagens ilustrativas"); ao trocar pelo vídeo real, mantenha os nomes ou ajuste `INTRO_FRAME_COUNT`. `scroll-animation/` é a mesma intro como página avulsa.
- Camadas do Monte seu Bolo: `src/data/bolo-layers.ts`. Cada camada usa `public/layers/<id>.png` (hoje ilustração provisória; a foto real entra trocando o arquivo ou pelo `image_url` no painel). `useLayerSrc` (`src/lib/layer-photo.ts`) tenta a imagem, depois a padrão, e some se as duas falharem — nunca mostrar imagem quebrada. O 3D é só CSS (perspective + preserve-3d + translateZ), sem bibliotecas 3D.
- Use as fotos reais dos bolos. Depoimentos só reais, em `src/data/testimonials.ts`.
- Administração em `/admin` (`src/routes/admin.tsx`): senha só na variável de ambiente `ADMIN_PASSWORD` (nunca no código), conferida no servidor por server functions em `src/lib/admin-auth.ts`; sessão em cookie httpOnly assinado (`src/lib/admin-session.ts`). Não coloque dados de clientes nem senhas no bundle do navegador.
- WhatsApp flutuante para clientes: `src/components/WhatsAppWidget.tsx`.
- Pedidos: regras puras em `src/lib/order-flow.ts` (status, estoque, bloqueio do PENDENTE; coberto por `src/test/order-flow.test.ts`) e server functions em `src/lib/orders-server.ts` (`placeOrder` público; listar/mudar status/confirmar pagamento/verificar estoque só com sessão). Os pedidos ficam no mesmo banco do catálogo (`getOrdersStorage`, chave `ondina:orders` ou `.data/orders.json`). O servidor recalcula preços pelo catálogo — o navegador só manda ids e quantidades. Painel: `src/components/admin/AdminOrders.tsx`.
- Frete: `src/lib/shipping.ts` (grátis só em São Miguel Arcanjo; fora dela, só Retirada no Local).
- Cardápio editável: entidades e CRUD puro em `src/lib/catalog.ts`; banco em `src/lib/catalog-store.ts` (Upstash Redis pela REST ou `.data/catalog.json`); API REST em `src/routes/api/catalog.*` com regras em `src/lib/catalog-api.ts`; a rota raiz carrega o catálogo e chama `applyCatalog` antes de desenhar — `products`/`BOLO_LAYERS` são a lista em uso, `DEFAULT_*` o padrão. Bolos novos de `DEFAULT_PRODUCTS` entram sozinhos no catálogo salvo (`withNewDefaults`, ao carregar); bolo padrão excluído pela equipe fica em `removed_defaults` e não volta. Fotos extras do mesmo bolo vão em `gallery` (setas no cartão) — nunca um cartão repetido. Código que só roda no servidor fica em `*.server.ts` ou `createServerOnlyFn`.

- Estoque: `stock` dos bolos (kg ou unidades; `null` = sem controle) em `src/lib/catalog.ts`; avisos no carrinho em `src/lib/stock.ts`. Quem decide é o servidor ao finalizar: tudo em estoque → "Aguardando pagamento" e o estoque baixa na hora; faltou → PENDENTE, sem baixar nada. PENDENTE nunca avança (nem pelo seletor, nem por "Confirmar pagamento"): só sai por "Verificar estoque" depois da entrada no estoque, ou cancelando. Cancelar devolve o estoque reservado. O cliente sempre escolhe a forma de pagamento; no pendente nada é cobrado antes da confirmação.
- Fotos enviadas pelo painel: `src/lib/image-api.ts` (`/api/images`, só JPEG/PNG/WebP conferidos pelos bytes) + `src/lib/image-resize.ts` no navegador. Tutorial do painel: `src/components/admin/AdminTutorial.tsx` — atualize-o quando mudar o painel.
- Pedidos do formato antigo (antes do fluxo com status): só leitura em `src/lib/order-store.ts` + `src/lib/orders.ts` (lista `ondina:orders` e hash `ondina:orders:confirmed`, ou `.data/orders.json`); o painel mostra em "Pedidos antigos". Pedidos novos ficam em `ondina:orders:v2` — nunca grave na chave antiga (ela é uma lista do Redis).
- Esgotado: `src/lib/stock-alert.ts` (link `wa.me` para a loja + webhook opcional `N8N_STOCK_ALERT_URL`, erro silencioso). Dispara quando o estoque chega a 0 pelo painel (catálogo) ou por um pedido (`persist` em `src/lib/orders-server.ts`).
